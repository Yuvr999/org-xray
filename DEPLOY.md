# Deployment Guide — ORG-XRAY

This guide covers deploying ORG-XRAY to [Render](https://render.com) using the included `render.yaml` blueprint.

---

## Prerequisites

- GitHub account with the repo pushed
- [Render](https://render.com) account (free tier works)
- A Google Gemini API key → get one free at [aistudio.google.com](https://aistudio.google.com)

---

## Deploy to Render (Recommended)

### 1. Push your repo to GitHub

```bash
git remote add origin https://github.com/YOUR_USERNAME/org-xray.git
git add -A
git commit -m "initial commit"
git branch -M main
git push -u origin main
```

### 2. Create a Blueprint on Render

1. Go to [dashboard.render.com](https://dashboard.render.com)
2. Click **New +** → **Blueprint**
3. Connect your GitHub repo
4. Render detects `render.yaml` automatically and creates two services:
   - **org-xray-api** — FastAPI Python web service
   - **org-xray-web** — React static site (CDN-distributed)

### 3. Set your Gemini API Key

After deploy:

1. Open the **org-xray-api** service
2. Go to **Environment** tab
3. Find `GEMINI_API_KEY` → click **Edit** → paste your key → **Save**
4. The service will automatically restart

---

## Environment Variables

| Variable | Service | How It's Set | Description |
|----------|---------|-------------|-------------|
| `SECRET_KEY` | API | Auto-generated by Render | JWT signing key |
| `GEMINI_API_KEY` | API | **Set manually** | Google Gemini API key |
| `GEMINI_MODEL` | API | `render.yaml` | Default model: `gemini-2.0-flash` |
| `DATABASE_URL` | API | `render.yaml` | SQLite path (no external DB needed) |
| `CORS_ORIGINS` | API | `render.yaml` | Comma-separated allowed frontend URLs |
| `VITE_API_URL` | Web | `render.yaml` | API base URL baked into the frontend at build time |
| `ENVIRONMENT` | API | `render.yaml` | `production` |

> **Important:** `VITE_API_URL` is baked into the frontend JavaScript bundle during `npm run build`. If you change it in the Render dashboard, you must trigger a **manual redeploy** of the web service to rebuild with the new value.

---

## Updating After Render Assigns Service Names

Render appends a short suffix to service names (e.g., `org-xray-api-abc123`). If your actual service URLs are different from the defaults in `render.yaml`, update these two values in the dashboard:

- **API service → Environment**: `CORS_ORIGINS` should include your actual web service URL
- **Web service → Environment**: `VITE_API_URL` should point to your actual API service URL (e.g., `https://org-xray-api-abc123.onrender.com`)

Then redeploy the web service to rebuild with the correct URL.

---

## Notes

- **Free tier sleep**: Both services sleep after 15 minutes of inactivity. The first request after sleep takes ~30 seconds to wake up — this is expected behavior on Render's free tier.
- **SQLite on Render**: The SQLite database file is stored on the service's ephemeral disk. Data resets on every deploy. For persistent storage, set `DATABASE_URL` to a PostgreSQL connection string (e.g., from [Supabase](https://supabase.com) free tier).
- **Upgrading**: Switch to Render's Starter plan (\$7/month) for always-on services with no sleep.

## Docker (Local / Self-Hosted)

```bash
# Full stack: API + frontend dev server + PostgreSQL + Redis
docker-compose up --build

# Production-like
docker-compose -f docker-compose.prod.yml up --build
```

Services:
- API → `http://localhost:8000`
- Frontend → `http://localhost:5173`
- API Docs → `http://localhost:8000/api/v1/docs`
