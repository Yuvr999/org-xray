# Phase 0 & Phase 1 Architecture Decision Record (ADR) - Baseline & Foundation

## Executive Summary
This document establishes the production architectural baseline for ORG-XRAY, detailing the monorepo structure, API design, database strategy, asynchronous service architecture, and operational foundation.

---

## 1. Monorepo Directory Structure

The repository has been structured as a production-grade monorepo:

```text
sharp-galileo/
├── apps/
│   ├── web/                     # React 19 + Vite + TypeScript Client SPA
│   └── api/                     # FastAPI Python Backend App
├── services/                    # Microservices & Workers (Invoice OCR, Process Mining, IoT)
├── packages/                    # Shared schemas, domain contracts, and test fixtures
├── infra/
│   ├── docker/                  # Multi-stage Dockerfiles for API and Web
│   ├── ci/                      # Deployment scripts
│   └── migrations/              # Infrastructure scripts
├── docs/
│   └── architecture/            # Architecture Decision Records & Design Docs
├── .env.example                 # Standardized environment configuration template
├── docker-compose.yml           # Local multi-container development environment
└── package.json                 # Monorepo workspace configuration
```

---

## 2. Backend Service Architecture (`apps/api`)

* **Framework**: FastAPI (Async Python 3.11+) with Pydantic v2 settings management and validation.
* **Logging**: Structured JSON logging in production environments, context-enriched logging in development.
* **API Versioning**: Enforced `/api/v1` namespace with OpenAPI specification autogenerated (`/api/v1/openapi.json`).
* **Health Monitoring**:
  * `/api/v1/health`: Liveness endpoint returning service status.
  * `/api/v1/ready`: Dependency readiness check validating PostgreSQL and Redis connectivity.

---

## 3. Data & Storage Layer

* **Relational Database**: PostgreSQL 16 managed via SQLAlchemy 2.0 async engine + Alembic migrations.
* **Cache & Message Broker**: Redis 7 async client for session state, rate limiting, and future task queues (Celery/RQ).
* **Document & File Storage**: Abstracted `BaseStorageAdapter` with `LocalStorageAdapter` for local development and S3 adapter interface for production document storage.

---

## 4. Verification & Testing Strategy

* **Frontend**: TypeScript compilation and Vite production build checks via `npm run build` in `apps/web`.
* **Backend**: `pytest` and `pytest-asyncio` suite verifying endpoint routing, database connection handlers, and health endpoints.
* **CI Automation**: GitHub Actions workflow (`.github/workflows/ci.yml`) executing multi-job build & test pipelines.
